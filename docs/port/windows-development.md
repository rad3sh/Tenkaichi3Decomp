# Windows CLI development environment

This repository can be prepared and validated without opening the Visual Studio IDE. The supported Windows
workflow uses the official Visual Studio Build Tools, MSVC, the Windows SDK, Ninja, Python, 7-Zip, SDL3,
DirectX Shader Compiler and CDB from WinDbg.

## First setup

From the repository root, run PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\windows\bootstrap.ps1
```

The bootstrap script installs official packages through `winget`, writes a timestamped transcript under
`logs/`, and runs the environment checks. To validate an already provisioned machine without installing packages:

```powershell
.\scripts\windows\bootstrap.ps1 -SkipPackages
.\scripts\windows\check-environment.ps1 -Json
```

The compiler and Windows SDK are installed outside the repository. Proprietary Microsoft binaries are intentionally not
committed. The scripts discover the standard Build Tools and Windows SDK locations. The SDL3 VC development archive is
kept in the ignored `.cache/SDL3/` directory because the repository needs its headers and import libraries to compile
Windows targets; it is downloaded from the official SDL release archive by the setup process.

## Direct3D 9 SDK validation

The Windows SDK supplies the Direct3D 9 header and libraries. The probe compiles and links against `d3d9.lib`
with debug information:

```powershell
.\scripts\windows\build-probe.ps1 -Architecture x64
.\scripts\windows\build-probe.ps1 -Architecture x86
.\scripts\windows\build-d3d9-bootstrap.ps1 -Architecture x64
```

Probe outputs and intermediate files are written to `build/windows/`, which is ignored by Git. The x86 probe is
important because the game's original data model uses 32-bit pointers in several places.

## Command-line debugging validation

CDB is included with WinDbg and is used directly from PowerShell:

```powershell
.\scripts\windows\debug-probe.ps1 -Architecture x64
```

The script creates a debug-symbol-enabled executable, launches it under CDB, breaks on `DebugBreak`, records the
last event and stack trace, and writes a timestamped log under `logs/`.

For a real executable, use the matching PDB and configure the symbol path before starting CDB, for example:

```powershell
$env:_NT_SYMBOL_PATH = "srv*C:\symbols*https://msdl.microsoft.com/download/symbols"
& $cdb -lines -c ".symfix; .reload; g; k; q" -- .\path\to\Tenkaichi3Decomp.exe
```

## Logs

- `logs/bootstrap-*.log`: package/bootstrap transcript.
- `logs/build-probe-*.log`: compiler and linker output.
- `logs/debug-probe-cdb-*.log`: CDB session output.
- `bt3_crash.txt`: existing crash report generated by the game process.

The `logs/` directory is local state and should not be committed. The scripts create it automatically.

The default D3D9/game window starts at `640x480`, a compact size close to the PS2 picture. Use
`BT3_WINDOW=WxH` to request another size, for example `BT3_WINDOW=1024x896`.
The visual backend probe also writes `build/windows/d3d9_backend_probe.ppm` and validates the PPM source pixels,
RGBA8 upload, DXT1 upload, target readback, and target copy. It is run with:

```powershell
.\scripts\windows\run-d3d9-backend-probe.ps1 -Architecture x64
```

## Comparing the D3D9 picture with OpenGL

`scripts/windows/compare-backends.ps1` runs the game once per back end with screenshots every n frames
(`BT3_SHOT`, `BT3_SHOT_DIR`), stops each run after a time, and writes `side_<backend>_NNNNN.png` (reference |
backend | amplified difference) under `build/windows/compare/`, with the mean difference per frame. The
attract-demo battle (`BT3_DEMO=1`, the default) is deterministic frame by frame, so the same frame shows the same
scene in every back end:

```powershell
.\scripts\windows\build-port-win64.ps1
.\scripts\windows\compare-backends.ps1 -Backends gl,d3d9 -Seconds 50 -Every 150
# the menus and a versus fight, without a controller: scripted presses (BT3_PAD) from the versus menu
$pad = ((0..7 | % { "$(650 + $_*60):start" }) + (0..50 | % { "$(1150 + $_*45):cross" })) -join ','
.\scripts\windows\compare-backends.ps1 -Menu -Seconds 90 -Every 90 -Env "BT3_MENU_MODE=38;BT3_PAD=$pad" -OutDir build\windows\menu
python scripts\windows\contact_sheet.py build\windows\menu\d3d9 build\windows\menu\sheet.png
```

`BT3_D3D9_DUMP_FRAME=<frame>` prints that frame's draw list (target, pipeline key, texture, bounding box) and
`BT3_D3D9_DUMP_VERTS=<draw>` one draw's vertices and texture, to find the draw behind a difference.

## Current scope

This branch adds the Windows CLI environment and the native D3D9 back end (`port/src/gs/gs_d3d9.c`, see
docs/port/README.md, "The Direct3D 9 back end"). It draws the same pictures as the OpenGL back end in the
compared scenes (title movie, menus, the demo battle, a versus fight with its HUD) and has the settings window
(F1). The existing Linux/macOS build remains unchanged.
